# v0.6.68 BRAT Prerelease Candidate

Status: implementation candidate. Not tagged or distributed. Integrated: No. Prereleased / Test-distributed: No. Verified: No. Released: No. Real Vault / remote / mobile verification is `NOT_VERIFIED`.

## Problem

Published v0.6.67 still failed `UNDO-BRIDGE-CROSS-SECTION-01`. T-0650 / E-20260816-0026 synchronized the forward afternoon-to-morning TaskMoved as D1 sequence 2392, but Ctrl+Z restored only dev Markdown. No inverse TaskMoved was created and remote/mobile stayed in morning.

The v0.6.67 capture-phase keyboard handler checked the generic editable target guard before recognizing Undo / Redo. Because that guard includes buttons, TaskBoard control focus could return before `preventDefault()` and allow Obsidian local Undo to run without the TaskChute semantic route.

## Candidate Fix

- Recognize Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z before the generic editable/button guard.
- Use one capture-phase routing gateway for TaskBoard non-text contexts.
- Consume an owned shortcut synchronously and invoke TaskChute Undo / Redo exactly once.
- Pass text inputs, textareas, selects, contenteditable elements, editors, and external overlays through to native behavior.
- Consume and block the shortcut while the TaskMoved semantic lifecycle is active so native Undo cannot mutate Markdown locally.
- Route command-palette TaskChute Undo / Redo through the same invocation gateway.
- Record bounded routing diagnostics without Markdown bodies or secrets.
