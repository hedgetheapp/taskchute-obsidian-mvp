# v0.6.73 BRAT Prerelease

## Purpose

v0.6.73 fixes the first visible TaskChute reload after an idle period when no relevant persisted data changed.

## Root cause

v0.6.72 removed direct idle-threshold reloads, but `queueExternalRefresh()` still advanced the TaskChute data generation for every queued source. Plugin `data.json` bookkeeping changes and deferred/internal notifications could therefore leave `data generation > rendered generation`. The first TaskBoard interaction treated that false mismatch as a real invalidation and ran the delayed disk-reload path.

## Runtime changes

- Classify invalidation sources instead of treating every external-refresh request as visible data change.
- Compare render-visible plugin-data state before and after loading `data.json`.
- Ignore cursor, outbox, diagnostics, and other nonvisual bookkeeping when the visible fingerprint is unchanged.
- Mark generation current after a successful TaskBoard open/render.
- Re-check generation when a delayed refresh timer executes; an already-current board performs no refresh.
- Preserve genuine TaskChute Markdown, definition, and Bridge visible-mutation refreshes.
- Preserve explicit manual reload and ordinary local immediate UI behavior.

## Diagnostics

- trigger and idle reason/duration
- data and rendered generation
- generation after render
- last invalidation source
- pending external refresh and Bridge dirty state
- refresh decision and refresh/no-refresh reason

## Minimal BRAT procedure

1. Install v0.6.73 and open TaskChute.
2. Leave it untouched for about five minutes without changing TaskChute data.
3. Perform the first click/touch.
4. Confirm reload, flash, scroll reset, and selection reset are all zero.
5. If this fails, stop. If it passes, run the separate backlog catch-up test and confirm all events apply/Ack with at most one visible refresh.
