# v0.6.62 BRAT Prerelease

v0.6.61実Vaultで確認された、same-section D&D保存後にrow section metadata欠落が`__no_section__`へfallbackし、TaskMoved enqueue guardで停止する問題を修正する固定試験配布物です。Verified済み安定版ではありません。

## Root cause

- T-0614 / E-20260815-0032の行commentに明示`__no_section__`が保存されていたとは限りません。
- `task-insert-below`で作成した行には`section` / `section_id`がなく、空値を`getSectionByNameOrId()`へ渡すとno-section definitionへfallbackします。
- same-section D&Dはcross-section D&Dと異なりmoved rowへsection metaを設定しないため、物理見出し`morning`とfallback row identity `__no_section__`が一般guardで不一致になりました。

## Changes

- same-section D&Dの保存前にraw row section metadataとphysical headingを比較します。
- `section_id`欠落をphysical headingから`section` / `section_id`へ補完し、ID一致時だけ欠落・古いsection labelを正規化します。
- 明示`__no_section__`または別section IDとの矛盾は補正せずblockします。row `section_id`が物理sectionと一致する場合に限り、欠落・古いsection labelを正規化します。
- 保存後Markdownから対象`entry_id`を一意再解決し、`task_id`、physical section、row section IDを再検証してからTaskMoved v4をenqueueします。
- `task-insert-below`の新規行には作成時からsection metadataを保存します。
- general `markdown_section_mismatch` guard、TaskMoved v4 identity / Ack / cursor、Alt move、section/date move、empty-source、Routine identityは変更しません。
- diagnosticsへphysical section、raw / parsed row metadata、resolved section、identity source、normalization、final guard resultを追加します。
