# v0.6.74 BRAT Prerelease

## Purpose

v0.6.74 prevents a no-change Edge-to-Obsidian focus return from refreshing an already-current TaskChute view.

## Root cause

The open-board polling baseline was initialized at startup but was not updated immediately after an internal board write. If Obsidian became unfocused before the next poll, background timer suspension could outlive the nine-second internal-write marker. The first resumed poll then compared the new file stat with the stale baseline and classified the already-rendered local write as an external Markdown change.

The reload path was `pollOpenTaskchuteBoardExternalChanges()` -> `queueExternalRefresh()` -> `flushExternalRefresh()` -> `patchTaskchuteViewsFromExternalSync()` -> existing `TaskchuteView.refresh()`. The view was refreshed, not recreated.

## Runtime changes

- Track bounded content fingerprints alongside open-board stat keys.
- Update both baselines immediately after internal file writes and successful initial TaskBoard rendering.
- Treat stat-only poll changes and delayed Vault events with identical content as `view_already_current`.
- Preserve actual external Markdown changes when content differs or comparison is unavailable.
- Preserve explicit manual reload and Bridge final refresh behavior.
- Keep existing TaskChute view instances on focus/visibility return.

## Diagnostics

- exact focus/visibility trigger and duration
- data/rendered generation and visible plugin-data fingerprint
- invalidation source and pending external refresh
- Bridge active/dirty state
- refresh decision and no-refresh reason
- exact reload method
- view instance reused/recreated state

## Minimal BRAT procedure

1. Install v0.6.74 and open TaskChute.
2. Switch to Microsoft Edge for about five minutes without changing TaskChute data.
3. Return to Obsidian.
4. Confirm reload, flash, scroll reset, and selection reset are all zero.
5. Stop on failure. Only after PASS, run one backlog catch-up test and require all events apply/Ack with at most one visible refresh.
