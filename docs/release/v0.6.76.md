# v0.6.76 BRAT Prerelease Candidate

## Purpose

v0.6.76 fixes a mobile backlog catch-up race where all inbound events could be physically applied, verified, Acked, and cursor-advanced while an older UI refresh later replaced the final board with a stale prefix.

## Confirmed root cause

The v0.6.75 final inbound UI update used a partial external patch that did not advance `TaskchuteView.refreshRunId`. A full refresh that started earlier from the A-only prefix could therefore finish after the final A/B/C patch and overwrite it. Overlapping focus/resume kickoff timers could also request a separate follow-up drain/session, splitting one physical catch-up across multiple final renders.

The six-event device evidence did not capture mobile physical Markdown. Code review found serial fresh-read apply/save/verify paths for TaskCreated and TaskUpdated and no stale physical-board overwrite path, so physical correctness is not claimed beyond the available evidence.

## Runtime changes

- Join overlapping startup, focus, visibility, and resume kickoff requests into the active or queued physical catch-up session.
- Preserve individual sequence-ordered fetch, apply, save, post-save verify, Ack, and cursor behavior.
- Block UI finalization while an apply/save/verify operation is active.
- Run at most one authoritative full refresh at terminal state when a visible mutation occurred.
- Advance the view refresh generation so an older prefix refresh cannot render after the final snapshot.
- Correct suppressed refresh diagnostics and record session joins, passes, sequence range, dirty transition, active operation count, and final generation state.
