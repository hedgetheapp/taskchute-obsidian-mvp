# v0.6.70 TaskBoard D&D Route Integration

Status: Integrated candidate. Integrated: Yes. Prereleased / Test-distributed: No. Verified: No. Released: No. Real Vault / remote / mobile verification is `NOT_VERIFIED`. No v0.6.70 tag or GitHub Release exists for this task.

## Problem

The immutable v0.6.69 BRAT build failed `UNDO-BRIDGE-CROSS-SECTION-01` before Ctrl+Z. The actual TaskBoard D&D left no active operation, pending batch, semantic history action, or lifecycle diagnostic. Source tracing showed that row targets used `moveTaskByDrag()`, while section-container and empty-section targets used the legacy `moveTaskToSectionByDrag()` path, which could persist Markdown and enqueue TaskMoved without entering the operation-scoped Undo lifecycle.

## Fix

- Route actual row, section-container, empty-section, and mobile quick drops through one TaskBoard dispatch gateway.
- Record bounded route diagnostics before lifecycle dispatch.
- Start the section-target operation and batch before its first persistent write.
- Reuse one semantic handoff finalizer for row and section single-task routes.
- Require exact semantic attachment, commit, fingerprint, and history-top verification before normal success.
- Preserve forward synchronization and install the existing Undo barrier if semantic handoff fails after the move becomes irreversible.
- Keep group D&D explicitly classified as a separate existing route.
