# v0.6.71 BRAT Prerelease

## Purpose

v0.6.71 fixes ordinary TaskCreated cross-device placement divergence. The sender captures exact relative placement from the row's actual post-save Markdown neighbors, and receivers reproduce and verify that placement before Ack.

## Runtime changes

- Adds optional `taskcreated_placement_version=1`.
- Supports `placement_mode=before-entry`, `after-entry`, and `only-in-section`.
- Uses exact `placement_anchor_entry_id` for before/after placement.
- Captures placement after local save and Markdown re-read, using predecessor first, then successor, then only-in-section.
- Validates exact anchor/date/section before inbound write and re-reads Markdown to verify identity, metadata, and adjacency before Ack.
- Preserves creation-time placement through rename merge, refresh, retry, and outbox serialization.
- Keeps no-version payloads on bounded legacy fallback; unsupported versions and unsatisfied exact contracts remain unacked.
- Keeps `creation_source` as diagnostic metadata rather than ordinary placement authority.
- Leaves the interrupt-continuation specialized exact-anchor flow unchanged.
- Does not migrate historical rows or emit compensating TaskMoved events.

## Discovery fixed

In v0.6.70, T-0667 / E-20260817-0015 TaskCreated sequence 2462 was applied by remote and mobile, but sender section-top order became peer section-bottom order because the payload had no exact placement contract. The date-move test was not started and remains blocked for that attempt.
