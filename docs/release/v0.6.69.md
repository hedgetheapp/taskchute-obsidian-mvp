## Problem

Published v0.6.68 routed TaskBoard Ctrl+Z through the intended gateway, but real-device `UNDO-BRIDGE-CROSS-SECTION-01` still failed. T-0651 / E-20260816-0027 synchronized the forward move as D1 sequence 2396. Ctrl+Z restored only dev Markdown because the top Undo action was semanticless, so no inverse TaskMoved was attempted.

The surviving diagnostics do not identify whether semantic build, attachment, or commit was the original failing stage. The code did establish an unsafe outcome: `moveTaskByDrag()` could warn about semantic handoff failure and still return success while an older generic pre-D&D snapshot remained usable.

## Fix

- Keep the v0.6.68 shortcut routing and v0.6.67 operation-scoped lifecycle.
- Store operation ID, batch ID, and semantic fingerprint on the committed action.
- Verify immediately after commit that exactly one matching semantic action is at Undo stack top.
- Reject a delayed exact generic pre-D&D snapshot during the bounded post-commit guard.
- If semantic handoff cannot be proven, remove only the exact unsafe generic snapshot and install an explicit Undo barrier.
- Return failure instead of reporting normal Undoable success.
- Record capture, commit, and history-invariant diagnostics without secrets or Markdown content.
