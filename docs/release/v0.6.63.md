# v0.6.63 BRAT Prerelease

v0.6.62実Vaultで確認された、reload後のmissing-metadata rowをsame-section D&Dするとphysical section contextを解決できずcommit前に停止する問題を修正する固定試験配布物です。Verified済み安定版ではありません。

## Root cause

- v0.6.62のrow normalizationはresolverへ渡されたdestination sectionを前提にしていました。
- row metadata欠落後のreloadではview/runtime taskの`section` / `sectionId`も空になり得るため、physical Markdownに正しい見出しがあってもhandoff前に`physical_section_unresolved`となる経路が残っていました。
- 画面add formが使用する`addTask()`は、v0.6.62でも日付note rowへ`estimate_min`しか保存していませんでした。`insertTaskBelowCurrent()`、section-top、copyはsection metadata保存済みですが、generic add pathは未対応でした。

## Changes

- D&D source/targetをcurrent Markdownからexact `entry_id`で一意解決します。
- source/destinationの物理見出しをsection contextの正とし、runtime section fieldsへ依存しません。
- same physical sectionを確認した後だけmissing row metadataを正規化します。
- 保存後はexact entry、`task_id`、physical section、row section、target orderを再検証してTaskMoved v4を1件enqueueします。
- generic `addTask()`の新規rowへ`section` / `section_id`を保存します。
- explicit wrong section IDと`__no_section__` conflictは補正せずblockします。
- general `markdown_section_mismatch` guard、Alt move、cross-section/date move、empty-source、Routine identity、Ack/cursor semanticsは変更しません。
