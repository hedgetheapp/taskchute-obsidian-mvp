# v0.6.66 BRAT Prerelease Candidate

Status: implementation candidate, not yet committed, tagged, or distributed. Real Vault / remote / mobile verification is `NOT_VERIFIED`.

## Problem

In v0.6.65, a same-date cross-section D&D produced a valid TaskMoved v4 and converged remote / mobile. Ctrl+Z then restored only the dev snapshot. No reverse TaskMoved was created, so dev returned to the source section while remote / mobile stayed at the forward destination.

Evidence: T-0647 / E-20260816-0024, forward D1 sequence 2383, event `ce3baf78-5d5e-4523-857d-116b16955226`, afternoon to night. The forward event was applied on remote / mobile; no reverse night-to-afternoon event existed after Undo.

## Candidate Fix

- Record exact TaskMoved semantic metadata in a single-task same-date D&D Undo history item: task / entry identity, before / after section, and entry/task order.
- Verify the current physical source state before snapshot restore.
- Restore the local snapshot, re-read Markdown, and verify exact target identity, physical heading, row metadata, and order.
- Enqueue a normal TaskMoved v4 with source `task-undo-confirmed-markdown-v4` or `task-redo-confirmed-markdown-v4` only after verification.
- Keep entry order authoritative for same-section reorder and duplicate task IDs.
- Treat exactly one unsent forward / inverse pair outside the active flush snapshot as net-zero only when task, entry, from/to, entry order, and task order are exact inverses. Preserve non-exact, multiple, active, sent, failed, or retried events and append the inverse later.
- Preserve current Bridge / outbox / cursor / logical-clock state inside the plugin-data save queue when applying an older Undo snapshot.
- Roll local files and history stacks back when post-restore verification or TaskMoved enqueue fails. Do not keep a local-only D&D Undo entry when semantic capture fails.
- Keep inbound TaskMoved writes outside local Undo history to prevent bounce.

## Supported Scope

- same-date cross-section single-task D&D Undo / Redo
- same-section single-task D&D reorder Undo / Redo
- distinct entry identities when task IDs are duplicated

Not covered: TaskCreated / TaskDeleted inversion, lifecycle inversion, Routine definition inversion, date-move rekey inversion, multi-select D&D, or arbitrary snapshot diff synchronization.
