# Codex向け main.js 分割レビュー・実装指示書（v0.4.79）

このファイルは、Codexに `main.js` 分割作業を依頼するための指示書です。

## 今回の目的

まずは `main.js` の分割方針をレビューし、次に安全な小単位で分割準備を進めることです。

現時点では、**いきなり大規模な実ファイル分割をしないでください**。

## 前提

- ベースは `taskchute-obsidian-mvp-integrity-diagnostics-v0.4.78.zip` 以降です。
- v0.4.79では分割計画書とこの指示書が追加されています。
- `AGENTS.md` を必ず読んでください。
- MarkdownはUTF-8として扱ってください。
- Windows PowerShellで読む場合は `Get-Content -Encoding utf8 .\AGENTS.md` を使ってください。
- `note_path` は正データではありません。
- `index.json` は再構築可能なキャッシュです。
- アーカイブ済みプロジェクトは既存表示のみ維持し、新規選択/再選択は不可です。

## まずレビューしてほしいこと

`docs/main-js-split-plan.md` を読み、以下を確認してください。

1. 分割フェーズに矛盾がないか。
2. 初期分割対象として危険な領域が含まれていないか。
3. Obsidianデスクトップ/モバイルで壊れやすい分割方式になっていないか。
4. `AGENTS.md` のルールと矛盾していないか。
5. `index.json` / 診断 / アーカイブ / コメント / ルーティンの仕様と矛盾していないか。

## 最初に実装するなら

最初の実装は、次のどちらかにしてください。

### 案A: ドキュメント強化のみ

- `docs/main-js-split-map.md` を新規作成。
- 現在の `main.js` の主要関数・クラスを責務別に一覧化。
- コード変更は `manifest.json` のバージョン更新とドキュメント追加のみ。

### 案B: main.js 内のセクションコメント追加

- `main.js` 内に大きな責務区切りコメントを追加。
- 既存関数の並び替えはしない。
- 挙動は変えない。
- `node --check main.js` を通す。

## まだやらないこと

- `src/` への本格移動。
- CommonJS相対requireによるランタイム分割。
- TypeScript化。
- ビルドパイプライン導入。
- View/Modalの大規模移動。
- `TaskchuteView` の分割。
- ルーティン設定モーダル群の分割。

## 分割を始める場合の推奨順

1. 日付/休日/カレンダー系の純関数。
2. ファイルI/O・履歴・エラーログ。
3. index再構築・整合性診断。
4. プロジェクトメタ・プロジェクトノート・アーカイブ。
5. コメント。
6. ルーティン。
7. View/Modal。

## 変更時の必須確認

- `manifest.json` のversionを上げる。
- `node --check main.js` を実行する。
- `AGENTS.md` をZIPに含める。
- 日本語Markdownを文字化けさせない。
- 実機確認できていない場合は「未実施」と明記する。

## 出力してほしい内容

- 実施内容
- 変更ファイル
- 変更した関数/クラス名
- 挙動変更の有無
- 未対応/TODO
- 確認結果
- 作成ZIP名

## v0.4.87以降の追加ルール

- 現時点では実ファイル分割を行わない。
- `src/`、`package.json`、`esbuild.config.mjs`、`tsconfig.json` は追加しない。
- `main.js` から `./src/...` を直接 `require` しない。
- 分割に見える作業をする場合も、まずdocsやセクションコメントの整理に留める。
- Obsidian実環境での有効化確認なしに、読み込み方式を変更しない。
